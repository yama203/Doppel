# Doppel

Mac のボリューム（外付けディスクなど）の中身を、別のボリュームへ丸ごとコピーするアプリです。中では `rsync` を動かしていて、「クローン（完全ミラー）」と「バックアップ（追加・更新だけ）」の2つのモードがあります。画面は全部日本語で、ステップ形式のウィザードで操作します。

## 主な機能

- **クローンモード**
  - コピー先のボリュームを APFS でフォーマットしてから、`rsync --delete` でコピー元とまったく同じ中身にします。
  - コピー先にデータがある場合（使用量が 1MB 以上）は、フォーマット前に確認ダイアログを出します。
- **バックアップモード**
  - フォーマットはしません。新しいファイル・更新されたファイルだけをコピーします。
  - オプションで「コピー元で削除されたファイルをコピー先からも削除する」（`--delete`）をオンにできます。デフォルトはオフで、コピー先にしかないファイルはそのまま残ります。
- **除外ディレクトリの設定**
  - 歯車アイコンから、コピーしない名前を追加・削除できます。設定はアプリを閉じても残ります（UserDefaults に保存）。
  - デフォルト: `node_modules`, `.Trash`, `.Trashes`, `.Spotlight-V100`, `.fseventsd`, `.TemporaryItems`, `.DS_Store`
- **Finder タグのコピー**
  - Homebrew 版 rsync（`/opt/homebrew/bin/rsync`）が入っていれば自動でそちらを使い、`--xattrs` で Finder タグなどの拡張属性もコピーします。
  - 入っていなければ macOS 標準の `/usr/bin/rsync`（`-E` オプション）を使います。確認画面に「Finderタグをコピーするには Homebrew 版 rsync が必要です」という案内が出ます。
- **進捗表示**
  - 転送済みファイル数と、いま処理中のファイル名を表示します。
  - 途中でキャンセルできます。
  - 一部のファイルがコピーできなかった場合（rsync の終了コード 1 / 23 / 24）は「一部エラーあり」の完了扱いになり、エラー内容が表示されます。

## 対応環境

- macOS 13.0（Ventura）以降
- ビルドには Swift 5.9 以降（Xcode か Command Line Tools）が必要です
- 外部パッケージへの依存はありません
- （任意）Homebrew 版 rsync … Finder タグもコピーしたい場合

```bash
brew install rsync
```

> `/opt/homebrew` だけを見ているので、Homebrew 版 rsync が使われるのは Apple シリコンの Mac で Homebrew を標準の場所に入れている場合だけです（コードから読み取った内容）。Intel Mac の `/usr/local/bin/rsync` は使われません。

## ビルド・インストール

### アプリ（Doppel.app）を作る

```bash
./build-app.sh
```

このスクリプトがやること:

1. `swift build -c release` でビルド
2. `Doppel.app` バンドルを作成（`Resources/Info.plist` とアイコンをコピー）
3. アドホック署名（`codesign --sign -`）

できあがった `Doppel.app` を開くか、`/Applications` に移動して使います。

```bash
open Doppel.app
```

```bash
mv Doppel.app /Applications/
```

### ビルドだけしたい場合

```bash
swift build -c release
```

### 配布されている zip を使う場合

`CLAUDE.md` のリリース手順では、GitHub Releases に `Doppel.app.zip` を添付することになっています。アドホック署名のみで公証（notarize）はしていないので、ダウンロードしたものは初回起動時に Gatekeeper に止められると思われます（推測）。その場合は Finder で右クリック →「開く」、または「システム設定 → プライバシーとセキュリティ」から許可してください。

## 使い方

1. **モードを選択**（ステップ 1/4）
   「クローン」か「バックアップ」を選びます。バックアップを選んだ場合は、削除同期のオン／オフもここで決めます。
2. **コピー元を選択**（ステップ 2/4）
   マウントされているボリュームが一覧で出るので、コピー元を選びます。右上の更新ボタンで一覧を読み込み直せます。
3. **コピー先を選択**（ステップ 3/4）
   コピー先を選びます（コピー元に選んだボリュームは一覧に出ません）。
4. **確認**（ステップ 4/4）
   モード、コピー元・コピー先、除外ディレクトリを確認して「クローン開始」／「バックアップ開始」を押します。
5. **実行**
   クローンモードでコピー先にデータがある場合は、「フォーマットして続行」するかどうかを聞かれます。終わったら「閉じる」で最初の画面に戻ります。

除外ディレクトリは、右上の歯車アイコン（除外設定）からいつでも変更できます。

## 注意点

- **クローンモードはコピー先のデータをすべて消します。** `diskutil eraseVolume APFS <ボリューム名> <マウントポイント>` でフォーマットします。コピー先の選び間違いに注意してください。
- **ボリューム一覧には内蔵ディスク（Macintosh HD など）も出ます。** アプリ側で「内蔵ディスクはコピー先に選べない」といった制限はしていません。
- **起動ディスクとして使えるクローンは作れないと思われます（推測）。** 中身は `rsync` によるファイル単位のコピーで、起動可能にするための処理（`asr` や `bless` など）はしていません。データ用ボリュームのコピー・バックアップ向けです。
- **権限について**
  - 管理者権限（sudo）は使わず、ログイン中のユーザーの権限で rsync を実行します。そのため、読めないシステムファイルや他ユーザーのファイルはコピーされず、「一部エラーあり」で終わることがあります。
  - コピー元によっては、「システム設定 → プライバシーとセキュリティ → フルディスクアクセス」で Doppel を許可しないと読めないファイルがあると思われます（推測。コード内で権限の要求はしていません）。
  - アプリはサンドボックス化されていません（entitlements なし）。
- **除外は名前で一致します。** `--exclude=名前` の形で rsync に渡しているので、ボリューム直下だけでなく、どの階層にある同じ名前のファイル・フォルダも除外されます。
- **進捗バーは「動いていることを示すだけ」です。** 全体の何％終わったかは出ません。分かるのは転送したファイル数と処理中のファイル名です。
- **コピー元とコピー先のボリュームのルート同士を同期します。** フォルダ単位のコピーはできません。
